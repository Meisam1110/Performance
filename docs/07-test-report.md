# ۷. گزارش آزمون — تطبیق خروجی سیستم با Merit.xlsb

```
npm test        # موتور محاسبه در برابر مقادیر واقعی فایل
npm run test:e2e   # اپلیکیشن ساخته‌شده در مرورگر واقعی
```

هر دو مجموعه در آخرین اجرا **کاملاً موفق** بودند.

---

## ۷.۱ روش

مقادیر مرجع مستقیماً از `Merit.xlsb` استخراج شده‌اند
(`tools/extract_merit.py` → `tests/merit-expected.json`) — یعنی آزمون در برابر
اعدادی اجرا می‌شود که Excel واقعاً تولید کرده، نه اعدادی که ما انتظار داشتیم.

داده عیناً همان‌طور که در فایل است وارد می‌شود — **بدون هیچ اصلاح یا استثنایی** —
و هر ستون محاسباتی هر ۱۰۰ نفر باید با Excel بخواند.

> نسخهٔ قبلی این گزارش دو سناریو داشت، چون یک ردیف (شمارهٔ پرسنلی ۴) نمی‌خواند.
> با اعلام قاعدهٔ حد نصاب اثرگذاری ویژه (AMB-01) آن اختلاف کاملاً توضیح داده شد و
> اکنون یک سناریوی واحد با تطابق کامل اجرا می‌شود.

## ۷.۷ اعتبارسنجی مستقل فایل خروجی

فایل تولیدشده با کتابخانهٔ مستقل `openpyxl` (پایتون) باز و بررسی شد:

```
sheets: ['Employee Master', 'Consolidated Questionnaire', 'روش پرداخت کارانه',
         'Validation Report', 'Summary', 'Configuration', 'Audit Log']
روش پرداخت کارانه:  103 × 19
  freeze_panes  = C2          (سطر عنوان و دو ستون اول ثابت)
  rightToLeft   = True
  autofilter    = A1:S103
  عرض ستون A    = 13.8   |  M = 24.8
  سلول A1       = «شماره پرسنلی»  bold=True  fill=FFEEF2F7
  M2 (ریال)     = 4,055,789,474      format='#,##0'
  L2 (امتیاز)   = 405.58             format='0.00'
  مجموع پرداخت ردیف ۲ تا ۱۰۱ = 100,000,000,000.00
```

هر هفت شیت راست‌به‌چپ‌اند و پنج شیت داده‌ای فریز عنوان دارند.

> **یادداشت فنی:** نسخهٔ رایگان SheetJS نه فریز پنل می‌نویسد و نه قالب عددی سلول.
> برای همین خروجی بدون فشرده‌سازی نوشته و سپس توسط `src/xlsx-postprocess.js`
> اصلاح می‌شود (تزریق `<pane>` و ساخت `styles.xml`). این ماژول در صورت مواجهه با
> هر ساختار ناشناخته، فایل اصلی را دست‌نخورده برمی‌گرداند تا خروجی هرگز خراب نشود.
> هزینهٔ این کار بزرگ‌تر شدن فایل است (۲۶۰ کیلوبایت به‌جای ۱۰۶ کیلوبایت برای ۱۰۰ نفر).
