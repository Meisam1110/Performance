# سامانه مدیریت کارانه — Karaneh Management System

جایگزین وب‌محور برای زنجیرهٔ محاسباتی `Merit.xlsb`: از ورود پرسشنامه‌های تیمی تا
تخصیص بودجه، تغییرات معاون بخش و گزارش نهایی پرداخت — بدون نیاز به باز کردن و
Copy/Paste دستی چند فایل Excel.

**اجرا:** فایل `karaneh-hr.html` را دابل‌کلیک کنید. بدون نصب، بدون سرور،
بدون اینترنت.

سامانه دو فایل دارد:

| فایل | دست چه کسی است | چه می‌کند |
|---|---|---|
| `karaneh-hr.html` | منابع انسانی | همهٔ اختیارات: طراحی پرسشنامه، تنظیمات، ورود پرسنل، و **تولید فایل معاون بخش** |
| `Karaneh-<گروه>-<دوره>.html` | معاون بخش | نسخهٔ کامل و مستقلی از همین سامانه که فقط پرسنل همان گروه را دارد؛ منابع انسانی آن را از فایل خود می‌سازد |

فایل معاون بخش «تولیدشده» است، نه ساخته‌شده با npm: در فایل منابع انسانی به
بخش «پرسنل» بروید و «تولید فایل معاون بخش» را بزنید.

> موتور محاسبه، خروجی `Merit.xlsb` را برای هر ۱۰۰ نفر و هر ۱۲ ستون محاسباتی
> **بدون هیچ استثنایی** بازتولید می‌کند.
> گزارش کامل تطبیق: [`docs/07-test-report.md`](docs/07-test-report.md)

## معماری

```
┌─────────────────────────────────────────────────────────────────┐
│  index.html / karaneh-hr.html              لایهٔ نمایش           │
├─────────────────────────────────────────────────────────────────┤
│  app.js          ─ وضعیت، نماها، نقش‌ها، سیم‌کشی، خروجی‌ها        │
│  ui.js           ─ قالب‌بندی، جدول تعاملی، مودال، اعلان          │
│  charts.js       ─ نمودارهای SVG داشبورد                        │
│  assets/         ─ قلم MTN Irancell (WOFF2) و نشان برند          │
├─────────────────────────────────────────────────────────────────┤
│  calculation-engine.js  ─ منطق محاسبه (خالص، بدون DOM)          │
│  excel-import.js        ─ خواندن فایل و نگاشت هوشمند ستون       │
│  templates.js           ─ تولید تمپلیت و اعتبارسنجی امضای آن    │
│  data-store.js          ─ ماندگاری، گزارش تغییرات، کنترل تکراری │
│  xlsx-postprocess.js    ─ فریز پنل، قالب عددی و کشویی خروجی     │
├─────────────────────────────────────────────────────────────────┤
│  IndexedDB (با پشتیبان localStorage)        │  SheetJS 0.18.5    │
└─────────────────────────────────────────────────────────────────┘
```

**اصل کلیدی:** `state` تنها ورودی کاربر را نگه می‌دارد. هر عدد مشتق‌شده از
`KaranehEngine.calculate()` می‌آید که پس از هر تغییر دوباره اجرا می‌شود. هیچ مقدار
محاسباتی ذخیره نمی‌شود، بنابراین هرگز با ورودی‌ها ناهماهنگ نمی‌شود — و دکمهٔ
«محاسبه» موضوعیت ندارد.

`calculation-engine.js` تابع خالص است: نه DOM می‌شناسد، نه ذخیره‌سازی، نه متغیر
سراسری. به همین دلیل هم در مرورگر اجرا می‌شود و هم زیر Node در آزمون‌ها.

### آماده برای Backend

موتور و مدل داده از لایهٔ ذخیره‌سازی جدا هستند. برای اتصال به Node.js/SQL کافی است
`read()` و `write()` در `data-store.js` پیاده‌سازی مجدد شوند؛ هیچ‌جای دیگری از
سیستم نمی‌داند داده کجا ذخیره می‌شود.

## مدل داده

```
State
├── period                 دورهٔ محاسبه، مثلاً «Q1 1405»
├── role, hodScope         سطح دسترسی و واحدهای تحت مسئولیت
├── package                شناسنامهٔ فایل تحویلی (در فایل معاون بخش)
├── budgetSource           منشأ عدد بودجهٔ اولیهٔ همان فایل
├── config                 تمام پارامترها — هیچ‌کدام در کد ثابت نیست
│   ├── budget, maxPerformanceScore, questionCount
│   ├── minPerformanceThreshold, thresholdMode
│   ├── gradeImpactFactor, specialImpactAmount
│   ├── specialImpactMinScore, specialImpactQuestion
│   ├── baselineCoefficientPerPerson, normalizationScope
│   ├── questions[]       { id, text, weight, scored }
│   ├── gradeMap          { '0':100, '1':150, ..., '4':350 }
│   └── answerScale       { 'خیلی کم':1, ..., 'خیلی زیاد':5 }
├── employees[]            Employee Master — کلید: employeeId
├── questionnaires[]       مجموعهٔ یکپارچه — کلید: employeeId + sourceFile
│   ├── q1..q5, specialProject, specialImpactAmount
│   ├── hodAdjustment, hodComment
│   └── excluded, duplicateResolution
├── importBatches[]        یک رکورد به ازای هر فایل، با نگاشت ستون‌ها
├── columnMappings         مترادف‌های عنوان ستون — قابل ویرایش مدیر
├── auditLog[]             کاربر، زمان، فیلد، مقدار قبلی/جدید، دلیل
└── finalizedAt
```

روابط: `employees.employeeId` ← `questionnaires.employeeId` (یک‌به‌چند تا زمان
تعیین تکلیف تکراری‌ها، سپس یک‌به‌یک). `importBatches.batchId` ←
`questionnaires.importBatchId`.

## تحویل به معاون بخش

منابع انسانی در «پرسنل ← تولید فایل معاون بخش» انتخاب می‌کند سازمان بر چه اساسی
تفکیک شود (واحد سازمانی، مدیر مستقیم، مدیر سطح ۱ تا ۳، یا سطح شغلی) و به ازای هر
گروه یک فایل HTML مستقل می‌گیرد.

هر فایل:

* **نسخهٔ کامل همین سامانه** است — صفحه خودش را کلون می‌کند و داده را به شکل
  `JSON.parse(...)` در `<head>` می‌نشاند؛ نیازی به build جداگانه نیست.
* در نقش «معاون بخش» باز می‌شود: طراحی پرسشنامه و تنظیمات سامانه در آن نیست، اما
  کل چرخه — تفکیک پرسشنامه، ورود پاسخ‌ها، اعتبارسنجی، محاسبه، تعیین مبلغ و
  خروجی — در دسترس است.
* **بودجه را در همان صفحهٔ «پرداخت کارانه»** می‌گیرد: عدد اولیه سهم همان گروه از
  تخصیص منابع انسانی است (نه بودجهٔ کل سازمان) و با تغییر آن، جدول و گزارش‌ها
  بی‌درنگ بازمحاسبه می‌شوند.
* بالای همان صفحه **گزارش به تفکیک سطح شغلی** دارد: نفرات، واجدان شرایط، میانگین
  امتیاز، مجموع دریافتی، میانگین هر نفر، کمترین، بیشترین و سهم از بودجه.
* در بخش «پرسنل» **تفکیک پرسشنامه بین مدیران** را دارد تا معاون فایل هر مدیر را
  جداگانه بسازد.
* بخش **راهنما**ی مخصوص معاون بخش را همراه خود دارد.

## دیکشنری محاسبات

| # | مفهوم | فرمول | تابع | ستون Excel |
|---|---|---|---|---|
| ۱ | امتیاز عملکرد | `Σ(پاسخ × وزن) / Σ(وزن)` | `calculatePerformanceScore()` | K |
| ۲ | عدد کارانه | `امتیاز × ۱۲۰ / ۴` | `calculateKaranehScore()` | L |
| ۳ | اثرگذاری ویژه | `بله و عدد کارانه ≥ ۱۰۰ ? ۳۰۰ : ۰` | `calculateSpecialImpact()` | N, O |
| ۴ | ضریب کارانه | `عدد کارانه + ویژه` | `calculateRawCoefficient()` | O |
| ۵ | متناسب‌سازی | `(Σضریب − n×۱۰۰) / n` | گذر ۲ | N5 |
| ۶ | ضریب نهایی | `ضریب − متناسب‌سازی` | گذر ۲ | R |
| ۷ | عدد گرید | `gradeMap[JL]` | `getGradeScore()` | F |
| ۸ | تأثیر گرید | `عدد گرید × ضریب تأثیر` | `calculateGradeImpact()` | G |
| ۹ | حد نصاب | `امتیاز > ۲ ? امتیاز : ۰` | `applyMinimumThreshold()` | I |
| ۱۰ | سرشکن حذف‌شدگان | `Σضریب حذف‌شدگان / تعداد واجدین` | گذر ۳ | J5 |
| ۱۱ | امتیاز عملکردی | `ضریب نهایی + سرشکن` | گذر ۳ | K (شیت ۲) |
| ۱۲ | امتیاز کل | `تأثیر گرید + امتیاز عملکردی` | `calculateTotalScore()` | L (شیت ۲) |
| ۱۳ | دریافتی اولیه | `امتیاز کل / Σامتیاز × بودجه` | `calculateBudgetAllocation()` | M |
| ۱۴ | اختلاف معاون | `دریافتی اولیه − مبلغ تعیین‌شده` | گذر ۵ | O |
| ۱۵ | سرشکن معاون | `Σاختلاف / تعداد بدون تغییر` | گذر ۵ | O5 |
| ۱۶ | کارانه نهایی | `مبلغ تعیین‌شده` یا `دریافتی + سرشکن` | گذر ۵ | Q |
| ۱۷ | کنترل بودجه | `Σکارانه ≤ بودجه` و هیچ مقدار منفی | `validateBudget()` | Q5 |
| ۱۸ | سقف مجاز تغییر | `مبلغ فعلی + کمترین دریافتی × تعداد` | `maxAllowedAdjustment()` | — |
| ۱۹ | گرد کردن به ریال صحیح | بزرگ‌ترین باقیمانده، با حفظ جمع کل | `roundedPayouts()` | — |

## توسعه

```
npm install          # فقط برای اجرای آزمون‌ها (Playwright)
npm run build        # ساخت karaneh-hr.html از ماژول‌های src/
npm test             # موتور در برابر مقادیر واقعی Merit.xlsb
npm run test:e2e     # اپلیکیشن ساخته‌شده در Chromium
npm run test:all     # هر دو
```

**فایل‌های src/ را ویرایش کنید، نه `karaneh-hr.html` را.** آن فایل خروجی
`tools/build.js` است.

برای توسعه با ماژول‌های جدا: `npm run serve` و سپس `src/index.html`.

```
src/
  index.html              نسخهٔ ماژولار برای توسعه
  styles.css              RTL، تفکیک بصری ورودی و محاسباتی
  calculation-engine.js   منطق محاسبه — خالص و قابل آزمون
  data-store.js           IndexedDB، گزارش تغییرات، کنترل تکراری
  excel-import.js         SheetJS + نگاشت هوشمند ستون
  xlsx-postprocess.js     فریز پنل و قالب‌بندی عددی خروجی
  templates.js            تولید تمپلیت Excel، شیت BARS و اعتبارسنجی امضا
  charts.js               نمودارهای SVG داشبورد (بدون کتابخانه)
  ui.js                   قالب‌بندی، جدول تعاملی، مودال
  app.js                  وضعیت، نماها، نقش‌ها، سیم‌کشی، خروجی‌ها
tools/
  extract_merit.py        استخراج داده و مقادیر مرجع از Merit.xlsb
  build.js                ساخت فایل تک‌فایلی
tests/
  engine.test.js          تطبیق موتور با Excel
  ui.e2e.js               آزمون سرتاسری در مرورگر
  merit-expected.json     مقادیر واقعی استخراج‌شده از Merit.xlsb
sample-data/
  merit-sample.json       ۱۰۰ رکورد نمونه (نام‌های ساختگی)
```

## امنیت داده

* تمام داده در مرورگر کاربر می‌ماند (IndexedDB، با پشتیبان localStorage).
* هیچ درخواست شبکه‌ای وجود ندارد؛ SheetJS به‌صورت درون‌خطی در فایل قرار گرفته است.
* فایل‌ها فقط با انتخاب صریح کاربر خوانده می‌شوند و جایی آپلود نمی‌شوند.
* خروجی Excel یا JSON فقط با اقدام کاربر تولید می‌شود.
* گزارش تغییرات هر تغییر مؤثر بر مبلغ را ثبت می‌کند.
* هر فایل حافظهٔ خودش را دارد: فضای ذخیره‌سازی با شناسهٔ همان فایل تفکیک
  می‌شود، بنابراین فایل منابع انسانی و فایل‌های معاونان — حتی وقتی همه از روی
  `file://` باز شوند — کار یکدیگر را بازنویسی نمی‌کنند.
* فایل معاون بخش فقط پرسنل همان گروه را در خود دارد؛ داده‌های بقیهٔ سازمان اصلاً
  در آن فایل نیست.

**فایل‌های حاوی داده واقعی پرسنل در مخزن نگهداری نمی‌شوند.** فایل‌های مرجع شامل
نام و کد ملی افراد واقعی‌اند و `.gitignore` آن‌ها را کنار می‌گذارد. دادهٔ نمونهٔ
مخزن (`sample-data/`) نام‌های ساختگی دارد.
